Privacy Policy

Under the Ordinary Automation · Effective 28 October 2026

Under the Ordinary Automation (“the application”) is a private tool that the owner of the Under the Ordinary YouTube channel (“the owner”) uses to upload, schedule, analyze and improve the channel's videos. This policy explains what Google and YouTube data the application accesses, and how it uses, stores, shares, protects and deletes that data. The application is not offered to the public. The owner is its only user.

1. YouTube API Services

The application uses YouTube API Services: the YouTube Data API, the YouTube Analytics API and the YouTube Reporting API. By using the application, the owner agrees to be bound by the YouTube Terms of Service. Google's handling of data is described in the Google Privacy Policy.

2. Information the application accesses

The owner connects the application to the channel through Google OAuth and grants these permissions:

  • Manage your YouTube account (youtube). This is used to read the channel's ID, title, description, thumbnails and public statistics, to list and read the channel's own videos and their metadata, and to upload videos, thumbnails and captions and update their metadata, privacy status and scheduled publish time.
  • View YouTube Analytics reports (yt-analytics.readonly). This is used to read analytics for the owner's channel and videos: views, watch time, average view duration and percentage, audience retention, subscribers gained and lost, likes, comments, shares, and, where YouTube provides them, impressions and click-through rate.

For topic research, the application also reads public YouTube search results and public video statistics through the YouTube Data API.

The application does not access the owner's Google password, Gmail, contacts, Google Drive or any other Google service. It does not collect data about the channel's viewers, apart from the aggregated, anonymous statistics that YouTube Analytics provides.

3. How the information is used

  • To upload videos that the owner has approved, and to set their titles, descriptions, thumbnails, captions, privacy status and publish times.
  • To show the channel's analytics to the owner on a private, password-protected dashboard.
  • To analyze how the channel's own videos perform, and to suggest topics, titles and script improvements that the owner reviews.
  • To research possible video topics using public YouTube search results.

The application only creates, changes or deletes content on the channel after the owner approves it, and new uploads are private by default. Google user data is used only to provide these features to the owner. It is never used for advertising, never sold, and never used to develop, improve or train generalized artificial-intelligence or machine-learning models.

4. Sharing and third parties

The application does not sell, rent or share Google user data, except in these cases:

  • AI analysis (Anthropic Claude). To write scripts and recommendations, the application sends Anthropic's Claude service the channel's video titles, descriptions, scripts and aggregated performance metrics. This happens through the owner's own Claude subscription. OAuth tokens and credentials are never sent. The owner has turned off the Claude account setting that would let Anthropic use this data for model training. Anthropic's handling of data is described in the Anthropic Privacy Policy.
  • Legal requirements. Data may be disclosed if the law requires it.

The application's use and transfer of information received from Google APIs to any other app adheres to the Google API Services User Data Policy, including the Limited Use requirements.

5. Storage and security

  • All data is stored on a private server that the owner controls. It isn't stored with any third-party cloud service.
  • OAuth access and refresh tokens are stored in a file that only the application's operating-system account can read. They are never kept in source code or version control, never written to logs, and never shown in the dashboard.
  • Analytics and content data are kept in a database that accepts only local connections. The dashboard requires a password login.
  • All communication with Google APIs uses encrypted HTTPS connections.

6. Cookies

The application's private dashboard uses one strictly necessary session cookie to keep the owner signed in. The application doesn't use advertising or tracking cookies, and it doesn't place cookies on the devices of YouTube viewers.

7. Retention and deletion

  • Analytics and metadata for the owner's channel are kept only while the owner's authorization is active. At least every 30 days, the application checks that its authorization is still valid and that stored videos still exist on YouTube. Data it can no longer refresh is deleted within 30 days.
  • Public data from YouTube search results, used for topic research, is refreshed or deleted within 30 days.
  • If the owner revokes access or asks for deletion, all stored Google user data (including tokens) is deleted as soon as possible and within 7 days.
  • Deleting data stored by this application does not delete anything on YouTube. To delete videos or other content on YouTube, use YouTube or YouTube Studio.

8. Revoking access

Besides the deletion process above, you can revoke the application's access to your Google account at any time from the Google security settings page: https://security.google.com/settings/security/permissions. After access is revoked, the application can no longer reach the YouTube account, and its stored data is deleted as described in section 7.

9. Children

The application is not directed at children, and it doesn't knowingly collect personal information from children.

10. Changes to this policy

If this policy changes, the effective date above will be updated. If the application starts using Google data in a new way, the owner's consent will be obtained again before that happens.

11. Contact

Questions or complaints about this application's privacy practices: open an issue at github.com/M-Waleed7/M-Waleed7.github.io/issues. For deletion requests, the issue only needs to say that deletion is requested; do not post personal data in it.
